# AI Agent Instructions for graphlite-node

## Project Overview

This is a Node.js native addon (via napi-rs) providing JavaScript/TypeScript bindings for [GraphLite](https://github.com/GraphLite-AI/GraphLite), an embedded graph database with ISO GQL (Graph Query Language) support.

The package name is `@jakeboone02/graphlite-node`.

## Architecture

- **Rust side** (`src/lib.rs`): Uses napi-rs to wrap GraphLite's Rust SDK (`graphlite-rust-sdk` crate). Exposes `GraphLiteDB` and `GraphLiteSession` classes to JavaScript.
- **JS side** (`index.js`, `index.d.ts`): Generated by napi-rs build. The `index.d.ts` file provides TypeScript declarations.
- **Tests** (`__tests__/`): Bun tests exercising the bindings against a real embedded GraphLite database.

## Key Dependencies

- `graphlite` (Rust crate) — the core database engine
- `graphlite-rust-sdk` (Rust crate) — high-level SDK wrapping the core
- `napi` + `napi-derive` (Rust crates) — Node.js N-API bindings for Rust
- `@napi-rs/cli` (npm) — build tooling for napi-rs projects

## Building

```bash
bun install          # Install JS deps
bun run build        # Build native addon via napi-rs
bun test             # Run tests
```

The Rust build requires that the `graphlite` and `graphlite-rust-sdk` crates are available. The `Cargo.toml` references them via git dependency from the GraphLite repository.

## Code Conventions

- The Rust code in `src/lib.rs` uses `#[napi]` attributes to expose classes and methods to JavaScript.
- Error handling: Rust errors are converted to `napi::Error` and thrown as JavaScript exceptions.
- Query results come back as JSON from GraphLite's core. The Rust layer converts `Value` enum variants (String, Number, Boolean, Null, List, etc.) into `serde_json::Value`, which napi-rs automatically converts to JS values.
- Session management: `GraphLiteSession` holds an `Arc<QueryCoordinator>` and a session ID string. Sessions are closed explicitly or on drop.

## Testing

Tests use Bun. Each test creates a temporary database directory, seeds data,
runs GQL queries, and asserts results. Tests clean up after themselves.

## GraphLite GQL Syntax Notes

GraphLite implements ISO GQL. Key patterns used in tests:
- `CREATE SCHEMA /name` and `CREATE GRAPH /schema/name` for setup
- `SESSION SET SCHEMA /name` and `SESSION SET GRAPH /schema/name` to set context
- `INSERT (:Label {prop: value})` for node creation
- `MATCH (n:Label) WHERE n.prop = value RETURN n.prop` for queries
- `MATCH (a)-[:REL]->(b)` for relationship traversal
